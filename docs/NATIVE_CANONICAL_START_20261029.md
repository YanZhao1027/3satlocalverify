首先把 `saveCanonical` 单独接在实际完成的 `start` 之后，**真正执行 951 步**，输出：

- 栈 768、780、783 保存的规范化模数字完全相等，数值是 **3**，保留的规范字宽为 **2 位**。
- 栈 817 保存距离分母 **1,280,000**。
- 栈 781 为**10 个 `true` 比特**的一元循环计数。

## 什么通过了严格验证，什么仍未通过

**已经通过：** 上述所有真实指令执行与结果验证；具体原版清理与拷贝步数公式；Lean 内核检查的原版物理端口等价、逐操作码映射等价；单程序与独立原版子程序之间的 4+2 处完整状态交接核对；全部 6,135/7,085 步的独立全栈空间复算。其余 Lean 定理公理审计只允许 `propext`、`Classical.choice`、`Quot.sound`，没有添加 `sorry` 或不可信快捷证明。

**仍未完成：** 对独立连接器生成的全部 3,036／3,161 标签，证明它们**逐项等于**未经修改的上游 `StructuredCalls.compiled` 所生成的整张指令表。为尽可能严格，我们直接调用上游 `compiled LeafOuterProgram.start` 的原始 `code` 在 **5 个位置**作昂贵的对照（不是测试自家编译器）：

| 原版代码标签 | 直接比对结论 |
| ---: | --- |
| 3（入口） | **PASS** |
| 41（哈希入口） | **57 秒超时，未验证** |
| 677（调用返回处） | **PASS** |
| 678（清理入口） | **57 秒超时，未验证** |
| 3025（保存字宽入口） | **PASS** |

因此是 **3/5 个位置取得直接等价证据，2/5 因求值成本过高而未完成**，绝不是“3,036/3,036 操作码验证通过”。这两个超时**也不意味着存在不等价**。同一原版源码自身已有 `start_eval` 和 `canonicalStart_eval` 的形式化语义定理，但它们不能代替独立连接器的全位置相等性证明。后者是继续推进前应解决的明确验证任务。

**空间与时间不能混淆：** 125 位只统计虚拟栈中真实保存的布尔位，不包括 896 栈的管理开销、固定代码、完整 TM2 物理磁带／地址表示；Lean 进程峰值 RSS 约 7.9 GiB。上面的 6,135、7,085 是可复查的**源级位指令**，既不是论文图灵机带成本的完全实测，也不是对现代 SAT 求解器的实际加速。
