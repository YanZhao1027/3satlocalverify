# 2026-10-28: Moving beyond exhaustive SAT sampling

## Verified achievements

- `sample_ve.py` computes the full violation-count polynomial by variable elimination, eliminating local variables and multiplying/summing integer polynomial factors rather than enumerating all ambient assignments. It is a new Python implementation, NOT a kernel-certified translation of the original paper's Walsh/CRT leaf. Runtime is exponential in induced width and polynomial degree; worst-case SAT remains exponential.
- `regression_ve.py` passes 277/277 cases: 68 legacy, 84 connected 3SAT cases, 120 new random cases, and five connected 3SAT chains of 16, 32, 64, 128, 256 variables. The independent chain transfer-matrix oracle cross-checks all coefficients. At 256 variables it processed 1019 local assignments, 143901 polynomial coefficient multiplications, and finished the VE phase in ~0.116 sec; the count is 7442448147868944390163235886440032019063650821335827132081608786.
- `run_ve_crt.py` passes the VE coefficients to ORIGINAL OpenAI `SqrtLog.Reconstruction.run` in a prime-power modular ring (Hermite order 3). At 16 variables: q=17, precision=4, modulus=83521, 5 nodes, 12741 #SAT, all coefficients reproduced, 10899 source callback operations. At 32 variables: q=37, precision=7, modulus=94931877133, 11 nodes, 112892768 #SAT, full coefficient recovery, 114553 source callback operations. This is an experimental end-to-end data path; its Python sampler is not formalized in Lean.
- `ChainDP.lean` implements a generic four-state transfer algorithm for any commutative semiring coefficients. It proves `ChainDP.fast_eq_slow` against a full exponential path sum and `ChainDP.fold_duality` by induction; `ChainFinalAxioms.lean` confirms only `propext`, `Classical.choice`, `Quot.sound`. No `sorry`/`admit`.
- `ChainSAT.lean` instantiates that verified dynamic programming with Boolean-valued clause satisfaction on the same signed consecutive triple-variable family, with scalar weights in Nat (0/1). Its theorem `ChainSAT.satCount_correct` proves equality to the exponential path-sum specification, again only the standard three axioms. Running `ChainSATSmoke.lean` produced counts for n=8,11,16,32,256: 112,675,12741,112892768,7442448147868944390163235886440032019063650821335827132081608786; n=16,32,256 agree exactly with independently computed Python chain oracles. The 0/1 transfer itself is polynomial work for these path-width-2 formulas.
- `ProofElevenNativeTrial.lean` obtained the expected 11-variable CRT numbers with `native_decide`, but `#print axioms` shows extra `native_decide`-related axioms. It is NOT accepted as a trusted replacement for the three-axiom proof and remains a diagnostic only. The older whole-formula `by decide` approach remains blocked by reductions; no new general CRT correctness theorem was completed here beyond OpenAI's existing `Reconstruction.run_correct`.

## Scope / limitations

This is a meaningful execution demonstration for low-treewidth connected SAT and a formalized transfer-matrix identity, NOT an implementation or benchmark proof of the general worst-case 2^o(n) SAT algorithm. The factor-elimination source is Python and is tested but not verified by Lean. `ChainSAT.lean` proves equality to a weighted path sum; we have not separately proved its DIMACS parser/generator matches the exact 3SAT input format inside Lean.
